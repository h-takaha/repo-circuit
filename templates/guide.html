はじめの回路で使う言葉

practice-board は架空の回路です。変更提案と検査結果を用意してあり、実際のテストや本番更新は行いません。操作はメモリ上で再現し、再起動すると初期状態へ戻ります。

回路の部品GitHubの言葉意味
幹線main変更を合流する本線
分岐配線・はんだ点ブランチ・コミット作業用の分岐と、記録した変更
スイッチプルリクエスト（PR）変更を幹線へ取り込む提案
検査ランプCIの結果合格か失敗かを見る。合格だけで安全を保証しない
スイッチを閉じるという比喩合流（マージ）幹線への取り込み。本番反映（デプロイ）は別の段階

GitHubの Close pull request は、合流せずに提案を閉じる別の操作です。GitHub公式の説明 ↗

次の体験: 詳しい状態の回路で、未送電・本番の位置・作業場所を確認できます。そこに表示するパスやファイルも例示です。

作業台・GitHub・本番 — 1つのツールには3つの置き場がある 回路図の幹線は GitHub の main です。その上に立つ旗が本番はここまで（本番に届いている位置）を示し、作業台（この PC）にだけあってまだ送っていない分岐やはんだ点は点線で描きます（幹線で直接作業しているときは、幹線の上に作業台の旗が立ちます）。このアプリは作業台と本番を読むだけで、書き込みません。
工程表 — 分岐がいまどの段にいるか 「未送電」の数は、作業台にある GitHub のコピー（origin/…）と比べて数え、GitHub の幹線の直近のコミットにすでにあるものは引きます。このアプリは fetch しないので、コピーが古いと、それより古い分が実際より多く出ることがあります。そのときは配電盤の「未送電」に※が付き、回路図の作業台マーカーにGitHub のコピーを最新にする（fetch）のボタンが出ます。 回路図の下の表は、分岐ごとに次の6段を左から並べます。作業台（この PC）でしか分からない未コミット・未送電も、GitHub の検査や合流と同じ行で見えます。最大8行で進行中の作業を優先し、合流済みは通常3件、現在残る完了分岐が多ければ8行の範囲内で増やします。

本番デプロイ合流でできたはんだ点に、本番マーカーが追いついたか

古い合流記録は分岐名で絞って最大3ページ追加確認します。表示は最大60秒の記録を含み、分岐の撤去を確認・実行するたびに先端とスイッチを読み直します。証拠を取得できない分岐、先端が変わった分岐、開いているスイッチや作業台の新しい変更がある分岐は撤去を止めます。

変更を記録して本番まで届ける — 手順を覚えながら進める

回路図の下の同名ボタンから、ファイル選択（git add）、はんだ付け（コミット）、送電（push）、スイッチ作成（PR）、検査、合流、本番確認へ進みます。いまの状態に合う一段を表示します。今回の修正に含めるファイルだけ選び、変更の名前を入力してください。

作業台のコマンドは内容を確認してコピーし、PowerShellで実行します。その後「実行後、状態を読み直す」で次へ進みます。コピーだけでは完了になりません。GitHubへの操作は既存のブレーカーと確認画面を使います。案内するコミットには [no-push] [no-deploy] を付けますが、マージ後の定期自動配布は別です。本番の旗が追いついたら、実際の画面も確認します。

作業台を最新の幹線に揃える — 次の作業の準備

回路図の下にある同名のボタンを押すと、最新情報を受け取る（fetch）→ 幹線へ切り替える（switch）→ 前へ進めて更新する（merge --ff-only）の3段を案内します。「ターミナルから実行」で一つずつコピーし、自分のターミナルで実行します。アプリは実行しません。

未コミットの変更があるときは、先にその内容を確認して記録します。更新コマンドは実行時にも現在の分岐と未コミットを確認し、履歴が分かれていれば停止します。最後に回路図を再読み込みして、作業台の旗が幹線の先端に揃ったか確認します。修正用の分岐は残り、GitHubへの送信や本番の更新は行いません。

作業場所（worktree） — 手元に残る作業の置き場

ツールの「作業場所（worktree）」タブは、主作業場所と追加の作業場所を全件表示します。回路の分岐表示上限とは独立しています。「作業台の片付け」が扱う分岐・追跡記録とは別に、実際の場所と残っているファイルを確認できます。

取り込みは「確認済み」「合流記録あり・到達未確認」「取り込み未確認」「判定不明」の4状態です。手元の既定分岐の記録と実HEAD、合流記録を照合します。fetch は行わず、根拠と鮮度を詳細に表示します。確認済みでもファイルの退避や使用終了の確認は必要です。

ファイルは追跡中の変更・未追跡・除外対象の要約パス件数です。フォルダは1件、0は取得できた空結果、「未取得」は不明です。管理元はパスからの候補であり、使用状況を断定しません。

整理は、使用終了の確認 → 必要ファイルの退避と復元確認 → 管理元で作業場所を整理 → 必要なら残った分岐を整理、の順です。登録の整理（prune）とフォルダ削除は別操作です。この画面は一覧と案内だけを提供します。

ツールから実行 / ターミナルから実行 / コマンドで言うと 操作には2つのボタンがあります。ツールから実行は、このアプリが GitHub に書き込みます。ターミナルから実行は、同じ操作の本物のコマンド（git / gh）をコピーするだけで、アプリは何も実行しません。自分のターミナルに貼り付けて実行します。GitHub に書く操作は、コピーの前にもブレーカーを通り、止まる操作ではコピーもできません。 作業台（この PC）の分岐を切り替える・消す・GitHub に送る操作は、アプリが作業台に書き込まないので、ターミナルから実行だけです。 ボタンの下のコマンドで言うとは、そのボタンが裏で行う操作を本物のコマンドで書いた欄です。押す前に開いて読めば、画面の操作とコマンドの対応が覚えられます。開くだけでは何も起きません。入力欄がある操作は既定の入力で書いてあり、実際の内容は押したあとの確認画面に出ます。
