凡例 — 回路記号と GitHub の対応

覚えるのは1つだけ: 電気が本番ランプまで流れる＝あなたの変更が本番のツールに届く。

1付箋を貼る「直したい」を IC チップにする
= Issue 作成
2分岐を引く幹線から作業用の配線を出す
= ブランチ作成
3はんだ付け作業台で直して記録し、GitHub へ送る
= コミット・push
4スイッチを付ける「幹線に入れて」と依頼する
= プルリクエスト
5ランプを見る自動検査が緑になるのを待つ
= CI
6スイッチを閉じる通電・付箋が自動で完了
= マージ
作業台・GitHub・本番 — 1つのツールには3つの置き場がある 回路図の幹線は GitHub の main です。その上に立つ旗が本番はここまで（本番に届いている位置）を示し、作業台（この PC）にだけあってまだ送っていない分岐やはんだ点は点線で描きます（幹線で直接作業しているときは、幹線の上に作業台の旗が立ちます）。このアプリは作業台と本番を読むだけで、書き込みません。
工程表 — 分岐がいまどの段にいるか 「未送電」の数は、作業台にある GitHub のコピー（origin/…）と比べて数え、GitHub の幹線の直近のコミットにすでにあるものは引きます。このアプリは fetch しないので、コピーが古いと、それより古い分が実際より多く出ることがあります。そのときは配電盤の「未送電」に※が付き、回路図の作業台マーカーにGitHub のコピーを最新にする（fetch）のボタンが出ます。 回路図の上の表は、分岐ごとに次の6段を左から並べます。作業台（この PC）でしか分からない未コミット・未送電も、GitHub の検査や合流と同じ行で見えます。

作業場所（worktree） — 手元に残る作業の置き場

ツールの「作業場所（worktree）」タブは、主作業場所と追加の作業場所を全件表示します。回路の分岐表示上限とは独立しています。「作業台の片付け」が扱う分岐・追跡記録とは別に、実際の場所と残っているファイルを確認できます。

取り込みは「確認済み」「合流記録あり・到達未確認」「取り込み未確認」「判定不明」の4状態です。手元の既定分岐の記録と実HEAD、合流記録を照合します。fetch は行わず、根拠と鮮度を詳細に表示します。確認済みでもファイルの退避や使用終了の確認は必要です。

ファイルは追跡中の変更・未追跡・除外対象の要約パス件数です。フォルダは1件、0は取得できた空結果、「未取得」は不明です。管理元はパスからの候補であり、使用状況を断定しません。

整理は、使用終了の確認 → 必要ファイルの退避と復元確認 → 管理元で作業場所を整理 → 必要なら残った分岐を整理、の順です。登録の整理（prune）とフォルダ削除は別操作です。この画面は一覧と案内だけを提供します。

幹線main / 本線
全員の土台。右端が本番につながる。直接はんだ付けはしない。
分岐配線ブランチ
幹線から引き出した作業用の配線。何をしても本番には影響しない。
はんだ点コミット
変更を記録したセーブポイント。消えない。いつでも戻れる。
IC チップ（付箋）Issue
「直したい」メモ。トレイにあれば未着手、分岐に刺さっていれば対応中。
スイッチプルリクエスト / マージ
開いている＝合流の依頼中。閉じる＝マージ。閉じると幹線に電気が流れる。
検査ランプCI（自動チェック）
緑=合格、黄=検査中、赤=失敗。赤と黄のスイッチは閉じられない。灰色で「取得不可」=検査結果を読めない状態。検査なしとは異なり、アプリからは閉じられない。
本番ランプデプロイ先 C:\lab\run
いま動いているツール。自動デプロイ対象は、合流すると数分で更新される。
旗（本番・作業台）稼働クローン / 開発リポジトリ
本番と作業台の実際のコミット位置を示す。未送電が0でも作業台の旗を出し、本番と同じ位置なら上下に分ける。表示範囲外は位置を断定せず、その旨とコミット番号を示す。
点線の分岐・はんだ点未 push のブランチ / コミット
作業台（この PC）にだけあって、まだ GitHub に送っていない分岐やはんだ点。送るまでは GitHub にも本番にも無い。
錆びた配線放置ブランチ
長く手が付いていない分岐。合流するか、要らないか判断しよう。
作業台の片付け合流済みのブランチ
幹線に入りきった分岐を、回路図から外してここにまとめる。手元の分岐と古い記録（origin/…）は「ターミナルから実行」でコマンドをコピーして片付ける。GitHub に残る合流済み分岐の撤去はブレーカーを通す。新しい未送電・未コミット作業がある分岐は片付け候補にしない。
ショート（火花）コンフリクト
同じ場所を別々の分岐で直した状態。解消するまでスイッチは閉じられない。
ツールから実行 / ターミナルから実行 / コマンドで言うと 操作には2つのボタンがあります。ツールから実行は、このアプリが GitHub に書き込みます。ターミナルから実行は、同じ操作の本物のコマンド（git / gh）をコピーするだけで、アプリは何も実行しません。自分のターミナルに貼り付けて実行します。GitHub に書く操作は、コピーの前にもブレーカーを通り、止まる操作ではコピーもできません。 作業台（この PC）の分岐を切り替える・消す・GitHub に送る操作は、アプリが作業台に書き込まないので、ターミナルから実行だけです。 ボタンの下のコマンドで言うとは、そのボタンが裏で行う操作を本物のコマンドで書いた欄です。押す前に開いて読めば、画面の操作とコマンドの対応が覚えられます。開くだけでは何も起きません。入力欄がある操作は既定の入力で書いてあり、実際の内容は押したあとの確認画面に出ます。
